# はじめてのReact Todoアプリ

ReactとViteを使った、初心者向けの小さなTodoアプリです。TypeScriptで実装しています。

## 起動方法

Node.js 22.12以上の22系、または24系以降を使ってください。

```sh
cd react-simple-todo
npm install
npm run dev
```

ターミナルに表示されるURLをブラウザで開きます。

## できること

- Todoを追加（Enterキーでも追加できます）
- チェックボックスで完了・未完了を切り替え
- Todoを削除
- Todoのタイトルを編集（Enterで保存、Escまたは「キャンセル」で取り消し）
- 期限日を任意で設定・変更・解除し、「今日まで」「期限切れ」を表示
- 「追加順」「期限が近い順」で並べ替え（期限なしは最後、同じ期限は追加順）
- 「すべて」「今日まで」「期限切れ」「期限なし」で期限を絞り込み
- 全件数と未完了の件数を表示
- タイトルの部分一致で検索（英字の大文字・小文字は区別せず、検索語の前後の空白は無視）
- 「すべて」「未完了」「完了」で絞り込み（検索と組み合わせて使えます）
- 表示件数の確認と「条件をリセット」で全件表示に戻す
- Todoをブラウザに自動保存し、再読み込み時に復元
- 「未完了」「今日まで」「すべて」を1回で切り替え

### 画面の使い方

追加欄には最初にタイトルだけを表示します。期限を付けたい場合は「期限を追加」を開きます。「期限を外す」または期限入力中のEscで日付を消して閉じられます。追加後は期限入力を閉じ、タイトル欄へフォーカスを戻します。

「未完了」「今日まで」「すべて」は完了状態と期限条件をまとめて切り替えるショートカットです。検索語と並べ替えは維持します。完了済みだけの表示や細かな期限・並べ替えは「表示設定」を開いて選びます。設定を閉じても条件は維持され、一覧の上に現在の条件を表示します。設定内のEscで閉じると「表示設定」ボタンへフォーカスが戻ります。

一覧ではタイトルを中心に表示し、期限がない行の「期限なし」は省略します。編集画面では期限の有無を確認できます。保存に失敗した場合の案内は、見落とさないよう一覧より前に表示します。

タイトルは追加・編集ともに200文字までで、前後の空白を除いて保存します。空白だけのタイトルは保存できません。編集では日本語変換中のEnterで保存されません。Todoは追加・編集・完了切り替え・削除のたびにlocalStorageへ保存し、次にページを開いたときに復元します。検索語と絞り込み状態は保存しません。

保存先は同じブラウザ・同じオリジン（URLのプロトコル・ホスト・ポート）のlocalStorageです。別の端末やブラウザとの同期は行いません。ブラウザのサイトデータを削除すると、保存したTodoも消えます。

保存データが壊れている場合や形式が違う場合は、案内を表示して空の一覧で開始します。読み込み時には保存データを書き換えず、次にTodoを変更して保存できたときに置き換えます。localStorageが使えない場合も画面上の操作はできますが、保存に失敗すると案内を表示します。

### 並べ替え・期限の絞り込み

初期表示は追加順で、期限の条件は「すべて」です。検索・完了状態・期限のすべてに一致するTodoを表示します。

- **今日まで**：未完了で、期限が今日以前のTodo（期限切れも含む）
- **期限切れ**：未完了で、期限が昨日以前のTodo
- **期限なし**：期限が未設定または解除済みのTodo。完了状態は別の条件で絞り込みます。
- **期限が近い順**：期限の古いものから順に表示します。完了済みも同じ規則で並び、期限なしは最後、同じ期限や期限なし同士は追加順を維持します。

「完了」と「今日まで」「期限切れ」を組み合わせると該当なしになります。日付をまたいだときは期限の絞り込みも更新します。全件数・残り件数は一覧全体の値です。表示件数には条件から外れていても編集中のため表示を続けている行も含みます。

並べ替えや絞り込みで保存データや追加順を書き換えません。選択した表示条件は保存せず、再読み込みすると初期条件へ戻ります。「条件をリセット」では検索語・完了状態・期限条件・並べ替えをすべて初期状態へ戻します。

### 期限日の扱い

追加フォームでは「期限を追加」を開き、編集フォームでは期限日欄から設定できます。編集時は「期限を解除」で期限なしへ戻せます。編集フォームの変更は「保存」で反映し、「キャンセル」またはEscで取り消します。

期限日は時刻を持たない`YYYY-MM-DD`形式です。利用中のブラウザのローカル日付で判定し、期限当日は「今日まで」、翌日からは「期限切れ」と表示します。完了済みのTodoは期限日だけを表示し、強調を解除します。日付をまたいだときやタブへ戻ったときも表示を更新します。

既存データの期限日は未設定として読み込みます。不正な形式や実在しない期限日を持つ保存データは、ほかの不正な保存データと同様に案内を表示し、編集が成功するまで元の保存データを保持します。

### 複数タブでの編集

保存時にはWeb Locks APIでタブ間の処理を順番に行い、ロック内で読み直した最新データへ操作を反映します。`storage`イベントとタブへ戻ったときの再読み込みで表示も同期します。

- 別々のTodoの追加・変更は両方を残します。
- 同じTodoの完了状態は、ロック内で後から処理した指定を採用します。同時に「完了」にしても二重の切り替えで未完了には戻りません。
- 削除済みのTodoへの完了状態の変更は無視します。削除と状態変更が競合してもTodoは復活しません。
- タイトル編集と完了状態の変更は両方を残します。同じタイトルを編集した場合は、ロック内で後から処理した指定を採用します。削除済みのTodoへのタイトル編集は無視します。
- 編集中の入力は別タブの更新で上書きしません。検索語や完了状態の条件から外れても、編集中の行は保存・キャンセルまで表示を続けます。表示件数にはこの行も含みます。別タブで削除された行は編集を終了します。
- 編集中も最新の完了状態を表示し、切り替えられます。タイトル・期限日は変更した項目だけを保存し、触っていない項目には別タブの最新値を反映します。入力中の項目は上書きしません。キャンセルすると最新の保存済みの値に戻ります。終了後に条件から外れる行は一覧から消え、フォーカスを検索欄へ戻します。
- 期限日とタイトル・完了状態の変更はそれぞれ残します。同じ期限日を変更した場合はロック内で後から処理した指定を採用し、削除済みのTodoへの期限日の変更は無視します。
- 保存に失敗した操作は画面内で保持し、次の編集で最新データへまとめて反映を再試行します。
- 保存待ちの操作もすぐに画面へ反映します。同じTodoを二度クリックすると、ロック待ちの間でも元の完了状態に戻ります。保存中に追加した操作は保存結果で上書きせず、引き続き保存します。

Web Locks APIを利用できないブラウザや実行環境では、競合する書き込みを避けるため保存せず案内を表示します。画面上の操作はできますが、再読み込みすると未保存の変更は消えます。

## コードを読む順番

1. `src/main.tsx`：Reactの画面をHTMLに表示する入口です。
2. `src/App.tsx`：Todo一覧と追加・完了切り替え・削除の操作を画面につなぎます。
3. `src/components/TodoForm.tsx`：入力文字の状態と追加フォームを管理します。
4. `src/components/TodoItem.tsx`：1件のTodoを表示します。
5. `src/types/todo.ts`：複数のコンポーネントで共有するTodoの型です。
6. `src/style.css`：見た目とスマートフォン向けの調整です。
7. `src/components/TodoFilters.tsx`：検索・よく使う表示・折りたたみ式の表示設定です。
8. `src/utils/filterTodos.ts`：検索・完了状態・期限で絞り込み、表示順を整えます。
9. `src/utils/todoStorage.ts`：保存データの確認・読み込み・保存と失敗時の処理です。
10. `src/hooks/useStoredTodos.ts`：Todoの状態・タブ間同期・操作の順次処理と保存の再試行を管理します。

## 学習ポイント

- **useState**：入力文字とTodo一覧を保存します。更新関数を呼ぶと画面も更新されます。
- **useState(loadTodos)**：初回表示時に保存済みのTodoを読み込みます。
- **useEffect**：他タブの保存を受け取るイベントを登録・解除します。
- **useRef**：未保存の操作と連続操作の処理順を保持します。
- **Web Locks API**：最新データの読み込みから保存までをタブ間で順番に処理します。
- **JSON.stringify / JSON.parse**：Todoの配列と保存用の文字列を変換します。読み込み時には型とIDの重複も確認します。
- **onChange / onSubmit / onClick**：入力・送信・クリックに応じて関数を実行します。
- **map**：Todo一覧を表示したり、指定したTodoの完了状態を変えたりします。
- **filter**：指定したTodoを除外したり、未完了の件数を求めたりします。
- **スプレッド構文**：元の配列やオブジェクトを直接書き換えず、新しいものを作ります。
- **key**：Reactが各Todoを識別できるよう、一意のIDを渡します。
- **type Todo**：IDとタイトルは`string`、完了状態は`boolean`として定義します。
- **useState<Todo[]>**：Todoの配列を状態として保持することを指定します。
- **FormEvent<HTMLFormElement>**：フォーム送信イベントの型を指定します。
- **props**：親の`App`から子のコンポーネントへ、データや関数を渡します。

### propsの流れ

`App`は`TodoForm`に`onAdd={addTodo}`を渡します。フォームを送信すると、`TodoForm`が`onAdd(title)`を呼び、`App`がTodo一覧を更新します。入力文字は`TodoForm`内で管理します。

`TodoItem`には`todo`と`onToggle`・`onDelete`・`onRename`・`onSetDueDate`などを渡します。チェックや削除の操作ではTodoのIDを、編集ではIDと変更した値を渡します。編集中の入力は`TodoItem`内で管理し、一覧への変更は`App`から保存処理へ渡します。

`TodoFormProps`と`TodoItemProps`で、受け取るデータや関数の型を定義しています。

JSXを含むTypeScriptファイルの拡張子は`.tsx`です。`tsconfig.json`で型チェックの設定を管理します。

検索語・完了状態・期限条件・並べ替えは`App`の状態として管理します。`filterTodos`で一致するTodoを取り出し、編集中の行も含めて`sortTodos`で表示順を整えます。元の保存用一覧は変更しません。編集終了後に行が条件から外れる場合は、保存後のタイトルと期限日で判定し、検索欄へフォーカスを戻します。

## 動作確認

1. 文字を入力して「追加」を押すと1件表示され、入力欄が空になる。
2. Enterキーでも追加でき、空白だけの入力では追加できない。
3. チェックすると取り消し線が付き、残り件数が減る。再度チェックすると戻る。
4. 「削除」で対象のTodoだけが消える。最後の1件を消すと空の案内が表示される。
5. 「Reactの勉強」と「買い物」を追加し、検索欄に「react」を入力すると前者だけが表示される。「 REACT 」でも同じ結果になる。
6. 検索中に「完了」を選ぶと完了済みの一致するTodoだけが表示される。該当しない場合は「条件に一致するTodoはありません。」が表示される。
7. 「未完了」表示中にTodoを完了にすると一覧から消え、残り件数と表示件数が更新される。「完了」で再び表示される。
8. 「条件をリセット」を押すと検索欄が空になり、「すべて」に戻る。検索や絞り込みではTodo自体は削除されない。
9. Todoを追加して再読み込みすると復元される。完了状態の変更と削除も再読み込み後に維持される。
10. 絞り込み中にTodoを変更して再読み込みしても、非表示だったTodoが残っている。最後の1件を削除して再読み込みすると空の一覧になる。
11. 開発者ツールでlocalStorageの`react-simple-todo.todos`に不正なJSONや形式が違うデータを設定して再読み込みすると、案内が表示され、空の一覧からTodoを追加できる。
12. ブラウザの保存制限などでlocalStorageへの書き込みが失敗した場合は、案内が表示されても追加・完了切り替え・削除ができる。
13. 同じページを2つのタブで開き、同時に別々のTodoを追加する。両方のタブと再読み込み後の一覧に2件とも残る。
14. 同じTodoの完了切り替えと削除を別のタブで同時に行う。再読み込みしても削除したTodoが復活しない。
15. 別タブでWeb Lockを保持したまま、同じTodoを二度クリックする。画面はすぐに元の完了状態に戻り、ロック解放後と再読み込み後もその状態を維持する。
16. 「編集」でタイトルの入力欄にフォーカスが移り、Enterまたは「保存」で更新される。再読み込み後も新しいタイトルが残る。
17. Escまたは「キャンセル」で変更を取り消せる。空白だけでは保存できず、日本語変換中のEnterでも保存されない。
18. 検索中にタイトルを変更すると検索結果も更新される。別タブの完了状態の変更と競合しても両方の変更が残り、削除済みのTodoは復活しない。
19. 「未完了」で絞り込み、編集中のTodoを別タブで完了にする。入力を保ったまま完了状態が更新され、保存後に行が消えて検索欄へフォーカスが移る。
20. 検索中に編集中のTodoを別タブで検索に一致しないタイトルへ変更する。入力は残り、保存・キャンセル後に行が消えて検索欄へ戻る。
21. Tabで編集フォームの保存ボタンやキャンセルボタンへ移動してからEscを押すと、編集を取り消せる。日本語変換中のEscでは取り消さない。
22. 期限付きで追加し、編集で変更・解除する。再読み込み後も期限日が維持され、キャンセルした変更は反映されない。
23. 昨日・今日・明日の期限を設定して表示を確認する。完了すると強調が解除され、未完了へ戻すと再び表示される。
24. 別タブで期限・タイトル・完了状態を変更する。入力中の項目は保たれ、触っていない項目は最新値を使って保存される。
25. 期限順に並べ替え、期限なしが最後、同じ期限が追加順になることを確認する。「追加順」に戻しても元の順番が保たれる。
26. 検索・完了状態・期限条件を組み合わせ、該当なしの案内と表示件数を確認する。リセットすると全条件と並べ替えが初期状態へ戻る。
27. 「期限切れ」表示中に期限を未来へ変えて保存すると行が消え、検索欄へフォーカスが移る。「期限なし」表示中の期限設定も同様に動く。
28. 編集中に別タブで期限を変えて条件から外す、または並び順を変える。入力は保持され、保存・キャンセル後は適切な位置へ戻る。
29. 追加欄の期限入力が最初は閉じていること、開いた後にEscで日付を消して閉じられること、追加後にタイトル欄へ戻ることを確認する。
30. 表示設定を閉じても選択した条件が分かること、Escで閉じてボタンへ戻れること、リセットで全条件を戻せることを確認する。

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`test`は複数タブの競合・保存失敗・復旧の回帰テストを実行します。`typecheck`は型の誤りを確認します。`build`は型チェック後に公開用ファイルを`dist`に作成し、`preview`はその結果をローカルで確認します。

編集画面のブラウザ回帰テストは、初回に`npx playwright install chromium`でブラウザを準備し、`npm run test:e2e`で実行します。別タブによるタイトル・完了状態の更新、入力の保持、保存・キャンセル後のフォーカス、フォーム全体のEsc操作とIME変換中の保護を確認します。既存のChromiumを使う場合は`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`に実行ファイルのパスを指定できます。
